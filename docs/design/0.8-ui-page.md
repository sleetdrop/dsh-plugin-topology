# 0.8 — topology page: align the browser surface with the DSH shell

This note records why the plugin's browser surface moved from a self-drawn
floating panel to a global `main` page, and which shell contracts that page
follows. It is the reference for the 0.8.0 UI change; the 0.7.0 service
inspector model is unchanged.

## Background

The plugin shipped its first panel while DSH was web-only. That panel owned its
own chrome: a fixed 840×680 card, a maximize/restore toggle, a close button and
a 16px viewport inset. The host now has a settled surface model and a window
chrome contract, so the old panel collided with it in two ways:

- On macOS the traffic lights are native and drawn over the page. At a 16px
  inset they sat on the panel's title row, next to a second pair of
  window-shaped controls.
- On Windows the main window uses `titleBarOverlay` (40px) with the native
  minimize/maximize/close at the top right, plus a caption menu bar at
  `z-index: 1100`. A fixed card at 16px put both over the panel's own header and
  controls.

The duplicate window controls were the visible symptom; the cause was choosing
a self-drawn window instead of a host surface.

## Surface decision

DSH now exposes five surfaces:

| Surface | Entry | Chrome | Example |
|---|---|---|---|
| Global main page | `sidebar.panellist` row + `main` keyed slot | page header, no close | Plugins |
| Modal | shared `Modal` / Settings | mask, overlay inset, close + Esc | Settings, install |
| Right column | `rightbar` (per Session) | tab strip, fullscreen presentation | Files, Terminal, session log |
| Bottom panel | `shell.bottom` | full width, own height | NodeJS Inspector |
| Anchored popover | `sidebar.footer.action` | 420×60vh menu surface | Cordis panel |

The topology is global (no Session binding) and needs a large canvas, so it is
a **global main page**: one `sidebar.panellist` row (`Plugin topology`) addresses the
`main` panel keyed `plugin-topology`. Leaving the page is ordinary sidebar
navigation; there is no maximize, close or mask.

## Chrome contract followed

- Page header: `28px` top padding, plus `--dsh-frame-top-clearance` (48px) on
  `html[data-platform='darwin']`, so nothing lands under the traffic lights.
  Windows already reserves the 40px caption above every column.
- The header is the window drag band via `data-window-drag`; the shell converts
  that mark into `-webkit-app-region: drag` and keeps interactive descendants
  (`button`, `input`, `[role=…]`) `no-drag`.
- No `--dsw-*` token is invented for the frame; the `--dsh-frame-*` variables
  are host-published and fall back to 0 in a plain browser.
- The page is inside the frame's centre column, so the OS chrome is never
  covered and the geometry no longer differs between macOS and Windows.

## Layout

```
Plugin topology                              [search] [TD|LR] [Export ▾]
Live plugin and service dependency graph.
──────────────────────────────────────────────────────────────────────────────
364 plugins · 524 dependencies · 1 unresolved · 0.004 · 7 · 5
legend: isolated · unresolved · PluginName[m,n…]
┌───────────────────────────────────────────────┬──────────────────────────┐
│                Graphviz canvas                │      Inspector           │
└───────────────────────────────────────────────┴──────────────────────────┘
```

The header carries the title, intro and three action groups (search, layout
direction, one Export menu). The metrics are the first content row; the legend
and the graph follow. The inspector stays a right-hand card inside the page.
The exports collapse into one menu so the header never wraps a lone format
button at a narrower centre column.

The header's 28px top step is the shell's page recipe and stays untouched;
the plugin-owned rows below it were compacted (12px content top, 8px gaps,
16px legend line) so the graph starts roughly 20px higher without pretending
to be a different kind of page.

## Behavior fixes found while reviewing the first page render

- **Fit now fits.** `fitView` used to floor at 1×, so a graph larger than the
  viewport was clipped at every edge and the fit control could not reveal it.
  It now fits the whole graph with a 24px margin, clamped only by the normal
  zoom floor. The initial view deliberately stays at **100%** (actual size) so
  labels are readable on arrival; at fit the pill collapses to the overview
  icon and expands on hover. The overview control is a toggle: while fitted it
  returns to 100%, otherwise it fits the whole graph. The zoom-level control is
  a percentage and always resets to 100%.
- **Narrower empty inspector.** With nothing selected the rail is 300px instead
  of 360px, giving the canvas more of a narrow centre column; a selected node
  still gets the full 360px.
- **Empty inspector is a selection prompt.** It uses the same three-node
  topology mark as the entry, with one node ringed, not the Plugins pinwheel:
  the state is "pick a node", not "this is a plugin". The title is "Select a
  node" (the graph also contains service nodes); the hint keeps the canvas
  click and `/` search affordances.
- **Collapsed rail is a handle, not a summary.** It keeps only the expand
  control and a vertical "Inspector" caption. The old first letter and state
  dot looked like data (a "W" and a green dot with no legend) and distracted
  from the canvas, which already marks the selection.
- **No "Overview" crumb.** The breadcrumb lists visited nodes only. Fitting the
  whole graph belongs to the zoom control; a mode switch inside a path read
  like an XPath reset, so `← / node / current` is the whole trail.
- **One export menu.** Three separate download buttons wrapped the JSON button
  onto its own line in a narrower window; `Export` opens a menu with SVG, DOT
  and JSON instead.

## Style alignment (scoped)

- Shared primitives: `Button` (exports/retry and the two-state TD/LR toggle
  group), `Menu` and the official icon set (close, chevron, download, search,
  fullscreen). `SegmentedControl` is not used: it renders a tablist and names
  tabpanels, which a layout direction does not have; a `role="group"` pair of
  `aria-pressed` buttons is the correct toggle semantics, and the active segment
  uses the business-primary fill with white text (not the charcoal primary
  Button variant, which reads as an action rather than a view mode). The entry row uses a
  local three-node topology glyph, distinct from the Plugins row's official
  pinwheel; primitives has no graph/network icon. Local glyphs
  remain only where primitives has no match: the entry topology mark, the
  empty-inspector select-node mark, the zoom minus/plus pair and the history
  back arrow.
- Tokens: `--dsw-radius-*` (panel/md/sm/xs), `--dsw-elevation-panel` for
  floating surfaces, `--dsw-focus-ring-*` for keyboard focus, 0.5px borders for
  cards and rows, and `--ds-font-family-code` for code.
- Type: page title 20/500, intro 13/20, metric values 16/600, labels 12; the
  9–9.5px floor was raised to 10–10.5px. Graphviz text keeps its own size but
  follows `--dsw-font-family` on screen; the exported SVG keeps Helvetica.
- Graph contrast was raised in both themes: light edge labels use
  `--dsw-alias-label-secondary` (`#61666b`) over `#cfd3d6` strokes; dark edge
  labels use `#cfd3d6` over 20% white strokes. Node labels use the theme
  primary text color.
- The legend's `[42]` sample was a hardcoded placeholder since the first
  scaffold; it is now the pattern `PluginName[m,n…]` with the copy
  `m、n 为本次运行内的实例创建序号` / `m, n are instance creation ordinals in
  this run`. "Instance" is the DSH-facing word for a Cordis fiber, and
  "creation" is deliberate: the number is the fiber creation order, not the
  activation order.
- Not in scope: inspector information architecture, Graphviz layout, and a
  global motion system.

## Semantic color language (Cordis-aligned)

The viewer used to spend red on things that are not failures. The rule now is
simple: **red means a real problem**, everything else is a state or a relation.

- **Lifecycle** follows DSH's status markers: ACTIVE is `state-success-primary`
  (green, the "done" state); FAILED is `state-error-primary` (red);
  LOADING/UNLOADING is `state-business-primary` (blue, "ongoing"); PENDING and
  DISPOSED are neutral `state-idle`/label colors. PENDING is the normal
  "waiting for required services" state in Cordis, so it is not amber/red; the
  missing provider is what gets the red outline.
- **Direction** is categorical: indigo is a dependency (upstream), ochre is a
  dependent (downstream). The canvas paints incoming edges amber, outgoing
  edges indigo, the inspector's Dependents section turns its active header amber,
  and the startup timeline uses the same pair.
- **No separate deferred state.** A provider created after the consumer is
  still a dependency; on the timeline its mark sits to the right of the selected
  mark, and the x-axis already carries creation order. There is no fourth role,
  no lighter-indigo state, and no red/error wording. Cordis deferred loading is
  normal; a later dependency needs no special label to be understood.
- **The startup strip is a rug, not a histogram.** All marks are 2px hairlines
  at one height; the 32-bin density heat was removed because a run creates one
  fiber per ordinal, so the gradient was flat and switched on only for the
  unusual cases that are already well served by the lists. Every mark is the
  same 2px width; the selected mark is colour-only, with no background band or
  white separator (the separator covered adjacent fringes). The strip is
  static: the inspector's text rows are the target. Hovering or focusing a node
  dependency/dependent row pulses the matching mark on the selected blink's
  500ms shutter (repeating until the pointer/focus leaves) and highlights its
  graph edge; service provider/consumer rows pulse their matching marks too.
  Clicking the row selects it. In node mode, merged providers/dependents
  contribute every instance ordinal; when the rendered label is capped with
  `…`, the whole same-name group is used, and the hover matches the group by id
  or multi-ordinal label. Service mode keeps the exact bipartite endpoints:
  same-name instances that do not touch the service are not marked. The selected lines wait 320ms for the eye to travel from
  the canvas to the inspector, then blink twice at a 500ms cursor interval when
  the selection set changes; it does not replay on hover, direction or theme
  changes (remounting the inspector does replay it). Under
  `prefers-reduced-motion` neither pulse runs, and the hovered mark keeps a
  static role-coloured halo. The strip is a chart: its marks are hidden from
  assistive technology; the legend and the inspector's row labels carry the
  role and ordinals, and the rows are the keyboard/pointer targets; colour is
  the visual encoding only.
- **Service health**: a critical single-provider service is a warning (amber);
  a plain single provider is informational (neutral); a healthy service is
  success green. A missing provider is an error (red).
- The legend, row labels, graph highlight, inspector sections and startup
  timeline now share this vocabulary, so the same hue means the same thing
  wherever it appears.

## Compatibility

- New peers: `@deepseek-ai/dsh-client-ui-layout` (the `main` slot) and
  `@deepseek-ai/dsh-client-ui-primitives` (the shared controls); both are
  `^0.2.1-rc.2`.
- The client bundle now requires the primitives module, which is part of the
  shell's module table; `scripts/check-client-externals.mjs` lists it
  explicitly rather than widening the check.
- `dsh.client.inject` adds the layout package so the `main` slot is declared
  before this plugin registers into it.
- No model-facing or host-service change in this release.
